# 给 Kimi 的 UI 设计提示词 v2

以下内容可以完整复制给 Kimi。第一轮只要求视觉方案和交互原型，不实现后端、窗口捕获、数据库或真实 AI 调用。

---

你是一名资深 Windows 桌面产品设计师和 WPF 交互设计师。请为开源项目 **MahjongAgent / 麻将观察助手** 设计第一版高保真 UI。

请先理解一个最重要的产品决定：

> 产品采用“双界面形态”。主窗口是配置、运维和牌局可视化仪表盘；悬浮助手是牌局进行时的核心功能。

不要把产品设计成需要用户每巡打开主程序、输入手牌或向聊天机器人提问的工具。系统会在后台主动监控目标麻将窗口、持续更新牌局状态并提前计算建议。

## 一、产品背景

用户第一次选择一个麻将游戏窗口后，系统利用多模态视觉识别牌桌布局、手牌、弃牌、副露、癞子和规则，并保存为长期 `WindowProfile`。再次看到相同窗口时自动加载档案，不从零理解。

首个规则集是武汉红中赖子杠，可能包含：

- 开口；
- 二五八将；
- 癞子；
- 皮；
- 红中杠；
- 开口翻或口口翻；
- 承包和大胡。

系统提供推荐弃牌、听牌和进张、牌型路线、危险度、攻守和规则解释。它只观察和提示，不读取游戏内存、不注入游戏、不自动点击或出牌。

## 二、产品使用场景

### 配置和运维场景

用户打开主窗口：

- 配置多模态 API；
- 选择或检查目标窗口；
- 查看 WindowProfile；
- 调整规则；
- 查看识别和 API 健康度；
- 查看当前完整牌局状态；
- 诊断低置信度或状态矛盾；
- 复盘历史牌局。

### 牌局进行场景

主窗口可以关闭到托盘。系统继续在后台监控。悬浮助手吸附在目标游戏窗口边缘：

1. 平时显示很小的待机状态；
2. 轮到用户或出现重要风险时主动展开紧凑建议；
3. 用户通过全局快捷键呼出详细策略；
4. 用户无需输入牌面，也不需要点击“开始分析”；
5. 建议查看完毕后自动收起，不抢游戏焦点。

## 三、视觉方向

整体气质：专业、冷静、可信、低干扰的实时分析工具。

关键词：

- Windows 11 桌面应用；
- 深石墨色背景；
- 低饱和玉石绿色品牌色；
- 象牙白麻将牌；
- 琥珀色提醒；
- 红色只表示高风险或错误；
- 数据可解释；
- 对 AI 不确定性保持诚实。

避免：

- 金币、筹码和赌场意象；
- 大面积红金色；
- 夸张霓虹电竞风；
- “稳赢”“必胜”“绝对安全”等措辞；
- 卡通元素压过数据；
- 只能依靠颜色理解状态。

麻将牌使用原创简化矢量或占位图，不复制游戏平台素材。需要设计万、筒、条、东南西北中发白，以及普通、选中、推荐、危险、癞子、皮和低置信度状态。

## 四、设计 Token

请给出可直接映射到 WPF ResourceDictionary 的设计 Token：

- 主背景、次级背景、卡片和浮层背景；
- 主文本、次级文本和弱文本；
- 品牌、成功、提醒、危险和信息色；
- 4/8/12/16/24/32 间距体系；
- 按钮、输入框、卡片、弹窗、牌面和浮层圆角；
- 描边、阴影和半透明度；
- 中文字体、数字字体和字号层级；
- 麻将牌小、中、大三种尺寸；
- 动效时间和缓动；
- 紧凑模式与舒适模式的密度差异。

## 五、第一优先级：悬浮助手

悬浮助手是核心功能，必须优先设计并展示完整状态。

### 1. 待机胶囊

建议尺寸约 180×40，可吸附目标窗口边缘。

显示：

- 连接状态；
- 当前巡目；
- 识别健康度；
- 是否暂停；
- 可呼出的快捷键提示。

示例：

```text
● 监控中  第6巡  识别正常
```

要求：低干扰、可拖动、默认鼠标穿透、不抢焦点。

### 2. 紧凑建议卡

建议尺寸约 360×160。轮到用户时自动出现，数秒后收起。

必须显示：

- 推荐弃牌，作为最大视觉焦点；
- 当前向听/听牌状态；
- 有效进张数量；
- 风险等级；
- 识别与建议置信度；
- 展开详细理由的快捷键。

示例：

```text
建议打：九条                 94%
一向听 · 有效进张 12 张
上家风险：中
按 Alt+M 查看详细策略
```

### 3. 详细策略面板

建议尺寸约 420×520，从目标窗口侧边展开。

显示：

- 推荐动作及原因；
- 2至3个备选动作；
- 不同动作的牌效、收益和风险差异；
- 有效进张；
- 癞子、皮、红中和开口状态；
- 对手风险概览；
- 最近关键事件；
- “为什么”解释；
- 当前不确定信息。

离开焦点或再次按快捷键后收起。

### 4. 悬浮异常状态

分别设计：

- 识别中；
- 低置信度；
- 正在恢复状态；
- API 超时；
- 目标窗口丢失；
- 暂停监控；
- 当前信息不足，暂不提供强建议。

错误状态不能遮挡游戏操作，也不能持续闪烁。

## 六、第二优先级：主窗口仪表盘

主窗口是完整程序页面，基准尺寸 1280×800，最低尺寸 1024×640。它不是简单设置页，也不是局内唯一入口，而是控制、运维和完整可视化中心。

建议左侧导航：

1. 仪表盘
2. 当前牌局
3. 窗口档案
4. 牌局复盘
5. 规则与知识
6. 设置与诊断

### 1. 仪表盘首页

顶部持续状态：

- 后台服务运行状态；
- 当前目标窗口；
- WindowProfile 名称、版本和匹配度；
- 当前牌局状态；
- 暂停/恢复；
- API 状态；
- 隐私状态。

核心运维卡片：

- 捕获帧状态；
- 最近一次视觉识别时间；
- 多模态延迟；
- 本局 API 调用数和估算成本；
- 当前事件同步状态；
- 识别置信度趋势；
- 状态矛盾数量；
- 最近错误；
- 本地档案和数据占用。

同时提供当前建议摘要，但不要抢过悬浮助手的产品定位。

### 2. 当前牌局完整可视化

该页面用于观察和诊断 Agent 如何理解牌局，包含：

- 自家完整手牌；
- 癞子、皮和翻牌；
- 四家弃牌河；
- 四家副露；
- 当前行动玩家；
- 开口、翻数、巡目和承包关系；
- 已见牌统计；
- 当前推荐和备选动作；
- 危险度图；
- 最近事件流；
- 低置信度观察；
- Agent 建议历史。

这是一张结构化数字牌桌，不直接复制游戏原画面。

### 3. 捕获和识别诊断

设计可展开的运维区域：

- 目标窗口身份；
- 捕获尺寸、DPI 和帧率；
- 变化检测命中率；
- 当前多模态 Provider 和模型；
- 最近请求耗时；
- Observation 候选；
- 已接受和已拒绝事件；
- 状态校验结果；
- 重新同步按钮。

普通用户默认只看摘要，高级信息放在“诊断详情”中。

## 七、其他必须设计的页面

### 1. 首次启动与隐私引导

- 产品能力和边界；
- 多模态服务选择；
- API Key 安全存储；
- 默认不保存完整截图；
- 是否保存裁剪视觉样本；
- 开始选择窗口。

### 2. 目标窗口选择

- 窗口缩略图；
- 标题和进程；
- 已有档案匹配结果；
- 创建或加载 WindowProfile；
- 无窗口、最小化、权限不足状态。

### 3. 首次视觉标定

左侧牌桌预览，右侧标定步骤。标出手牌、弃牌、副露、癞子/皮、当前玩家和剩余牌数。支持自动确认、手动调整和暂时未知。

### 4. 识别纠错

- 模型候选牌；
- 局部视觉证据；
- 选择正确牌或未知；
- 仅修正本局；
- 同时改进窗口档案；
- 长期样本隐私提示。

### 5. WindowProfile 管理

- 档案名称、预览、规则、版本、匹配度；
- 最近使用和识别成功率；
- 视觉样本数量；
- 重新标定、复制、导出、回滚、删除。

### 6. 牌局复盘

- 结构化事件时间线；
- 当时的状态和建议；
- 用户实际动作；
- 风险变化；
- 跳转到任意巡；
- 标记识别错误。

### 7. 规则与知识

- 当前规则档案；
- 开口翻/口口翻；
- 癞子、皮、红中杠；
- 胡牌类型；
- 已验证和待确认规则；
- 来源冲突。

### 8. 设置与诊断

- API Provider 和模型；
- API Key；
- 全局快捷键；
- 悬浮层行为；
- 自动弹出策略；
- 捕获和隐私；
- 数据保留；
- 档案导入导出；
- 日志和诊断包；
- 开源许可证。

## 八、完整交互流程

请画出以下流程：

```text
首次启动
  → 配置 API
  → 选择窗口
  → 自动标定
  → 创建 WindowProfile
  → 后台开始监控
  → 主窗口可关闭到托盘
  → 牌局变化自动更新
  → 轮到用户时弹出紧凑建议
  → 快捷键展开详细策略
  → 牌局结束自动生成复盘
```

局内正常流程不得要求人工录入。

## 九、状态与可访问性

必须覆盖：

- 空状态；
- 加载状态；
- 正常监控；
- 低置信度；
- API Key 无效；
- API 超时；
- 无网络；
- 目标窗口丢失；
- UI 布局漂移；
- 牌局状态矛盾；
- 暂停；
- 牌局结束。

风险必须同时使用文字、图标和颜色。不要把“绿色”写成绝对安全，只能使用“较低风险”或“相对安全”。

## 十、WPF 技术约束

最终客户端使用 C#、.NET 10 和 WPF：

- 设计可映射为 XAML 和 ResourceDictionary；
- 优先 Grid、Border、ItemsControl、ContentControl 等可复用结构；
- 不依赖浏览器专属 CSS 滤镜；
- 控件提供默认、悬停、按下、禁用、加载和错误状态；
- 悬浮窗需要透明、置顶、可穿透、不抢焦点；
- 使用 Mock ViewModel，不写真实业务逻辑；
- 不访问窗口捕获、数据库或真实 API；
- 不把规则逻辑写进 code-behind。
