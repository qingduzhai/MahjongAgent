# UI 审核清单

## 产品信息

- 是否一眼看出当前正在监控哪个窗口；
- 是否明确显示监控、暂停、恢复和异常状态；
- 当前建议是否比详细解释更突出；
- 是否区分确定事实、模型推测和低置信度警告；
- 是否避免承诺“绝对不会放炮”。

## 牌局表达

- 手牌、癞子、皮、红中和推荐弃牌是否容易区分；
- 吃碰杠、开口数、翻数和最近事件是否可快速浏览；
- 危险度是否同时使用图标、文字和颜色；
- 是否支持不依赖颜色的可访问表达；
- 低置信度牌是否能直接进入纠错流程。

## 悬浮层

- 是否足够小，不遮挡麻将操作区；
- 是否默认不抢焦点；
- 是否存在紧凑、展开和隐藏三种形态；
- 是否能快速暂停和关闭提示；
- 是否在浅色、深色牌桌上都清晰可读。

## 长期记忆

- 是否显示当前匹配的窗口档案；
- 是否能看到档案匹配置信度和版本；
- 是否能重新标定、回滚或删除档案；
- 是否清楚告知哪些视觉样本会被本地保存；
- 是否提供训练数据贡献的独立开关。

## 完整状态

- 空状态；
- 首次标定；
- 正常监控；
- 轮到用户；
- 低置信度；
- API 失败；
- 窗口丢失；
- 牌局结束；
- 无网络或未配置 API Key。

## 工程交付

- 所有尺寸、间距、圆角、颜色和字体形成设计 Token；
- 每个页面标注最低窗口尺寸；
- 每个组件包含默认、悬停、按下、禁用、加载和错误状态；
- 不使用有版权风险的游戏截图、麻将素材或品牌资产；
- 输出能够映射到 WPF/XAML，不依赖浏览器专属布局技巧。
