# UI 协作边界

## Codex 负责

- 总体架构和工程约束；
- 领域模型、规则、状态机和策略；
- 捕获、多模态、存储和 Agent 编排；
- ViewModel 接口与数据契约；
- UI 方案审核、代码集成、测试和最终交付；
- Git 历史和跨模块一致性。

## Kimi 负责

第一阶段：

- 视觉方向；
- 设计 Token；
- 页面信息层级；
- 高保真 UI 稿；
- 组件状态和交互说明。

审核通过后的第二阶段：

- WPF ResourceDictionary；
- 纯 UI XAML；
- 控件模板和样式；
- 使用 Mock ViewModel 的前端交互；
- 视觉回归截图。

## Kimi 不负责

- 修改领域模型和规则；
- 实现真实窗口捕获；
- 调用真实多模态 API；
- 访问 SQLite 或密钥存储；
- 直接修改 `GameState`；
- 将业务规则写入 XAML code-behind；
- 自动操作游戏窗口。

## 合并门槛

每轮 UI 交付依次经过：

1. 产品信息层级审核；
2. 武汉麻将术语和示例审核；
3. 正常、空、加载、低置信度和错误状态审核；
4. WPF 可实现性审核；
5. 可访问性和隐私审核；
6. XAML 静态检查和视觉回归；
7. Codex 集成到正式 ViewModel。

Kimi 第一轮只交设计方案，未经审核不生成完整工程代码。
