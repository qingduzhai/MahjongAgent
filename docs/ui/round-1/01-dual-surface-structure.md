# 01 双界面产品结构说明

> 对应提示词 v2 第一、二节与 ADR-0002。本文件回答一个问题:用户在任何时刻面对哪个界面、它承担什么、不承担什么。

## 1. 结构总览

```text
                    ┌────────────────────────────────────┐
                    │ GameState + DecisionSnapshot(只读) │
                    └───────────────┬────────────────────┘
                                    │ 同一份只读 ViewModel
              ┌─────────────────────┴─────────────────────┐
              │                                           │
┌─────────────▼─────────────┐               ┌─────────────▼─────────────┐
│ 主窗口(控制与运维仪表盘)│               │ 悬浮助手(局内核心功能)  │
│ 1280×800 / 最低 1024×640  │               │ 吸附目标窗口边缘,三层形态 │
│ 配置·诊断·档案·复盘·可视化│               │ 胶囊→紧凑卡→详细面板      │
└───────────────────────────┘               └───────────────────────────┘
        用户主动打开                                系统主动出现
        可关闭到托盘,后台继续运行            不抢焦点、默认鼠标穿透
```

## 2. 职责划分

### 主窗口 = 控制、运维、诊断、完整可视化

用户**主动打开**它来理解和干预系统:

- 首次引导与多模态 API 配置;
- 目标窗口选择、WindowProfile 管理与版本回滚;
- 规则档案查看(已验证/待确认);
- 捕获、识别、API、状态机健康度与成本;
- 当前牌局完整结构化可视化(观察 Agent 如何理解牌局);
- 低置信度诊断与识别纠错;
- 历史牌局复盘。

主窗口**不是**每巡请求建议的入口;没有"开始分析"按钮,也没有聊天框。

### 悬浮助手 = 牌局进行时的唯一建议界面

系统**主动驱动**,用户零录入:

1. 待机胶囊(180×40):常态最低存在感,报告"系统是否健康、第几巡";
2. 紧凑建议卡(360×160):轮到用户或出现重要风险时自动出现,数秒后自动收起;
3. 详细策略面板(420×520):用户按全局快捷键(`Alt+M`)呼出,焦点离开或再按即收起。

悬浮助手**不**承担配置、档案管理、复盘;这些一律回到主窗口。

### 托盘 = 后台运行的证据

主窗口关闭后最小化到托盘;捕获、识别、状态更新、策略计算、悬浮提示继续运行。托盘菜单只提供:打开仪表盘、暂停/恢复监控、呼出悬浮助手、退出。

## 3. 关键产品原则(所有稿件遵守)

1. **局内流程不要求人工录入**:牌面、事件、癞子/皮状态全部由后台观察与校验产生;用户只在"纠错"时介入,且纠错不阻塞局内建议流。
2. **结论优先,解释可展开**:任何界面先给推荐动作,理由折叠一层(快捷键或点击)。
3. **诚实表达不确定性**:区分"确定事实(事件溯源)""规则引擎计算(确定性)""启发式推测(带依据)""低置信度观察(可纠错)"四档,措辞禁用"稳赢/必胜/绝对安全"。
4. **悬浮层不遮挡、不抢焦点**:默认鼠标穿透;紧凑卡避开游戏手牌区与操作按钮区;异常状态静态呈现,不闪烁。
5. **任一界面都不推导牌局事实**:主窗口与悬浮助手只消费只读 ViewModel(ADR-0002 共享状态约束)。

## 4. 界面状态机(导航级)

```text
首次启动引导 ──→ 配置API ──→ 选择窗口 ──→ 首次标定 ──→ 创建WindowProfile
                                                          │
                                  ┌───────────────────────┘
                                  ▼
                        后台监控开始(悬浮胶囊出现)
                          │                       │
                  主窗口:仪表盘/牌局可视化      悬浮:胶囊 ⇄ 紧凑卡 ⇄ 详细面板
                          │                       │
                  可关闭到托盘(监控继续)      窗口丢失/低置信度→降级为状态警告
                                                          │
                                              牌局结束 → 自动生成复盘(主窗口查看)
```

详细组件级状态与流转见 [11-components-states-flows.md](11-components-states-flows.md)。

## 5. 主窗口信息架构

左侧导航六项(与提示词一致),每项的职责一句话:

1. **仪表盘**:系统是否健康、正在监控谁、花了多少 API 成本——30 秒看懂的运维首页;
2. **当前牌局**:结构化数字牌桌 + 推荐/风险/事件流,用于诊断 Agent 的理解;
3. **窗口档案**:WindowProfile 列表、详情、版本、样本与隐私;
4. **牌局复盘**:按巡回看的结构化事件回放;
5. **规则与知识**:当前规则档案、验证状态、来源冲突;
6. **设置与诊断**:API、快捷键、悬浮层行为、隐私与数据保留、日志诊断包。

顶部持续状态条(48px)跨所有页面:服务状态 · 目标窗口 · 档案匹配 · 牌局阶段 · 暂停/恢复 · API 状态 · 隐私状态——保证"一眼看出正在监控哪个窗口"。
