## 2. 数字牌桌区(696×696,`Brush.Bg.Surface` + `Radius.Card`)

**结构约定**(四家统一):每个方位 = 玩家信息行(名称/开口数/危险度档,图标+文字)+ 副露区(Tile.M,横置牌表示吃碰来源)+ 弃牌河(Tile.S 网格,按弃牌顺序从左到右、每行 6 枚,多张行自动换行;最新一张带 1px `Border.Strong` 外框)+ 红中杠徽标(`杠`角标计数)。

| 元素 | 规格 |
|---|---|
| 中心信息块 | 160×120,`Brush.Bg.Card`:巡目(Display 数字)、牌墙剩余(Font.Numeric)、翻牌/癞子/皮(Tile.M 各一枚 + 角标)、红中杠累计;**翻/癞/皮三牌是全局视觉焦点之一**,外圈 1px `Brush.Brand.Default`(40%) |
| 当前行动玩家 | 玩家信息行左侧 3px 品牌竖条 + `行动中` chip;自家回合额外在自家手牌区上方显示 `轮到你出牌` Body.Strong |
| 自家手牌 | Tile.L 横排,摸入牌与手牌之间留 12px 间隔 + `摸入` Micro 标签;癞子/皮带身份角标;低置信度牌(如 `9筒?`)琥珀虚线描边,点击直接进纠错弹窗(审核清单要求"低置信度牌可直接进入纠错流程") |
| 推荐标记 | 当前推荐牌带"荐"角标 + 绿描边;鼠标悬停手牌任一牌 → 悬停 tooltip 显示"打这张:进张 X 张 · 风险档"(由只读 ViewModel 提供,纯展示) |
| 弃牌河不可见状态 | 未开口/信息不足方位以 `Text.Tertiary` 标注 `信息不足`,河牌缺失张用虚线占位框表示,不虚构 |

**开口/翻数/承包关系**:每家信息行内嵌 `开口×N`、`翻 N`;存在承包关系时(如点炮包赔)在两玩家之间画 1px Warning 色连线 + `承包` chip(本局 Mock 未触发,线框保留)。

## 4. 状态覆盖

| 状态 | 呈现 |
|---|---|
| 空(无进行中牌局) | 牌桌区空态:`未检测到牌局 · 系统将在开局后自动构建` + 最近一局入口 |
| 识别中/恢复中 | 牌桌顶部 24px Info 条 `正在更新…`,各区域显示上次快照 + 角标时间戳 |
| 低置信度 | 低置信度观察卡出现;涉及区域(如手牌#9)虚线琥珀框 |
| 状态矛盾 | 页面顶部 Danger 条 `检测到 1 处状态矛盾:弃河计数与手牌数不符` + [查看差异] [重新同步];矛盾区域红色虚线框 + 文字说明 |
| 窗口丢失 | 整页灰显 + 居中 `窗口丢失` 卡 + [重新选择窗口] |
| 暂停 | 顶部 `已暂停` Warning 条;数据冻结于暂停时刻 |
| 牌局结束 | 顶部 `本局已结束 · 复盘已生成` + [查看复盘];牌桌定格终局状态 |

## 5. 与悬浮助手的边界

本页展示完整推理与诊断,但**不提供**"点我出牌/点我确认"类局内操作;唯一动作型按钮是纠错与重新同步(诊断行为)。局内建议以悬浮助手为准,避免用户每巡盯着主窗口。
