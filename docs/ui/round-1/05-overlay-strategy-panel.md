## 3. "为什么"抽屉(四层,与审核清单"区分确定事实/规则计算/推测/低置信度"对应)

1. **确定事实**:来自事件溯源的本局事实(手牌构成、已见牌);
2. **规则计算**:规则引擎确定性结果(向听、进张差值);
3. **推测判断**:启发式风险与对手倾向,必带依据与"推测"标记;
4. **参考经验**(新增,P0-4):本次建议检索到的历史经验——命中数量、最高相似度、代表 Episode 定位(档案/局/巡),链接到主窗口"记忆与学习"的 **Retrieval Audit** 详情;无命中时显示 `本次建议未参考历史经验,完全来自规则计算`(诚实空态)。

抽屉末尾**规则依据**行:每条规则标注 `本档案已确认` / `待确认`,并注明档案名——规则是 RuleProfile 数据,不是全局事实(P0-1)。

## 4. "问 Agent"追问(P1-2,仅 InteractiveOverlay)

```text
问 Agent:[为什么不打癞子?] [发送]
→ 回答(插入滚动区,等宽分隔):
  按本档案规则,癞子可以打出或作癞子杠(待确认);但打出会失去万能替代,
  有效进张虽不变,胡牌弹性显著下降,策略评为不推荐。—— 依据:当前
  GameState + 本档案规则 + 检索审计 #231。
```

- 输入框在 PassiveOverlay 不渲染(底栏仅显示快捷键提示);进入 InteractiveOverlay 才出现;
- 追问**只读**当前 GameState、DecisionSnapshot 与已检索记忆,**不修改任何牌局事实**(与 handoff-contract 边界一致);回答标注依据来源;
- 无网络 / API 超时:输入框禁用 + 原因文字(`追问需要多模态服务,当前不可用`);本地规则类问题(如"X 规则是什么")由规则引擎直接回答,不受网络影响。

## 5. 全部状态

| 状态 | 呈现 |
|---|---|
| 正常 | 如 §1 |
| 非关键不确定(P1-1) | 不确定条出现,写明`不影响首选弃牌`或`影响范围:…`;其余不变 |
| 关键不确定(P1-1) | hero 与备选区替换为 `▲ 关键信息不确定,暂停建议` + 缺失项 + `[✎ 纠正识别]`;不进张、不给等级;底栏追问仍可用(限只读解释) |
| 信息不足 | hero 替换为缺失项清单;备选/进张区灰显禁用 |
| 识别中/恢复中 | 顶部 24px Info 条 `正在重新识别牌桌…`,内容为上次快照 + `数据截至 3 秒前` |
| API 超时 | 顶部 Warning 条 `策略更新延迟,以下为最近一次计算结果`;追问框禁用 |
| 窗口丢失/暂停 | 面板不出现;已展开则收起并退回胶囊对应状态 |
| 空(无建议历史) | 标题栏 + `暂无建议:尚未轮到你或本巡无需决策` + 底栏 |

## 6. 交互规格(双模式)

- 呼出:全局热键(可配置,Mock 占位 `Alt+M`)→ 进入 InteractiveOverlay 并滑入(`Motion.Panel` 280ms `Ease.Out`);
- 收起:再按热键 / `Esc` / 点击面板外 / 无操作 30s(可配)→ 200ms `Ease.InOut` 滑出并回 PassiveOverlay;
- 滚动:中部 440px 区垂直滚动,标题栏与底栏固定;`为什么`抽屉行内展开,不撑破 520 总高(P1-4);
- 键盘(**仅 InteractiveOverlay 获得焦点后**):`↑↓` 在推荐/备选行间移动,`Enter` 展开该行解释,`W` 展开为什么,`C` 纠错,`/` 聚焦追问框,`Esc` 收起;
- 与紧凑卡互斥;面板展开期间紧凑卡不再自动弹。

## 7. WPF 映射要点

`OverlayHostWindow` 内面板模板:`Border(CornerRadius=12) > Grid(行:40 / * / 40)`;中部 `ScrollViewer > StackPanel` 分区 `ContentControl`;对手洞察与事件为 `ItemsControl`;进张条横向 `ItemsControl`;为什么抽屉为自定义 `Expander`;追问框为独立 `UserControl`(可见性绑定交互模式)。滑入动画用 `TranslateTransform`;窗口不参与游戏激活链。
