# 13 需要产品方确认的问题

> 对应提示词 v2 交付项 12。按对设计的影响程度排序;标注 ✅ 的表示本轮已按某个默认假设推进,确认后可能需要调整。

## A. 影响信息架构

1. **目标平台的牌张构成**:武汉红中赖子杠在不同平台是否含发财/白板、发财白板是否也作杠牌("红中发财杠"变体)?本轮稿件的 Mock 牌面只使用万/筒/条 + 红中/白板,刻意避开风牌与不确定规则。✅ 默认假设:基础变体 = 万筒条 + 中发白,红中必杠。
2. **悬浮助手默认吸附位置与遮挡清单**:不同平台的操作按钮区不同(右下/底部居中)。"默认右上内侧"是否需要按平台配置进 WindowProfile?✅ 已按可配置设计。
3. **自动弹出触发器范围**:本轮默认 `轮到自家` + `高风险提醒` 两类,`他人吃碰杠` 作为可关的可选项。是否认可?(对应提示词"轮到用户或出现重要风险时主动展开")
4. **是否需要英文界面**:全部文案本轮为中文。若开源后考虑 i18n,需在第二阶段把文案抽为资源(成本小,但影响 XAML 写法)。✅ 默认:仅中文,但建议文案即资源。

## B. 影响视觉与组件

5. **是否需要浅色模式**:麻将游戏本身有浅色牌桌,悬浮层 95% 深底在两色牌桌上都可读;但主窗口浅色模式工作量不小。✅ 默认:深色优先,浅色模式排入后续版本。
6. **牌面矢量风格确认**:原创简化矢量 = 圆角矩形 + 单色套色字符(万/筒/条 三分色 + 中发白固有色),不使用任何平台素材。是否认可"筒/条"用抽象圆点/竹节图案而非写实图案?(影响 TileView 工作量)
7. **MVVM 库选型**:建议 CommunityToolkit.Mvvm;若项目要求零依赖则手写 ViewModelBase。请定夺。
8. **数字字体**:Bahnschrift 为 Windows 10+ 自带,回退 Segoe UI Variable。是否接受?(纯系统字体,无打包字体的许可证问题)

## C. 影响交互细节

9. **紧凑卡自动收起时长**:默认 6s(3–15s 可调),风险提醒 4s。出牌完成后立即收起——"出牌完成"由事件检测判定,若识别延迟,卡片可能晚收。是否接受"识别到自家弃牌事件才收起,兜底 10s 强制收起"?
10. **低置信度时的默认行为**:本轮设计为"降级为倾向性建议 + 可纠错,不阻塞"。另一种选择是"低置信度时完全不显示建议"。产品倾向哪种?(ADR-0002 写的是"暂停强建议",本轮理解为:不给强建议,但可给标注过的倾向。请确认措辞与行为边界)
11. **全局快捷键默认值**:`Alt+M` / `Alt+P` / 按住 `Alt` 可交互。是否与目标平台常用键冲突?是否需要"游戏全屏时禁用呼出"选项?
12. **复盘数据保留期**:设置页默认 90 天(事件日志 30 天)。是否认可?(影响本地占用估算)

## D. 需要 Codex/工程侧确认

13. **UI 工程落点**:第二阶段 XAML 放在 `MahjongAgent.Platform.Windows` 内,还是新建 `MahjongAgent.UI` 项目供未来 Avalonia 替换?(ADR-0001 约束 Core 不引用 Windows 程序集,UI 放哪层需定)
14. **Mock ViewModel 数据契约**:本轮按 `GameState + DecisionSnapshot` 只读消费设计;请 Codex 确认 ViewModel 接口清单(12 号文件 §4 列出的 12 个)是否与领域侧计划一致。
15. **悬浮层截图合规性**:"视觉回归截图"会包含悬浮层覆盖在**真实游戏窗口**上的画面吗?合规上建议只在模拟牌桌(Mock 背景)上截图,避免真实平台素材进入仓库(与 CONTRIBUTING "不提交完整用户截图"一致)。请确认。
