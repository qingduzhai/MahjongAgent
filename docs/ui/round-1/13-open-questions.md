## C. 第三轮裁决(产品方直接定案,已落地)

第三轮复审结论:两个 P0(悬浮层交互模式、OpenAI-Compatible 配置)已关闭;本节原 3 个开放问题由产品方直接定案:

| # | 定案 | 落地位置 |
|---|---|---|
| 1 | **能力探测结果保存为 `LastProbe`**:打开设置页不重复调用;Base URL、Path、模型、认证、Key、输出模式任一变化立即失效,提示重新验证(后端 `OpenAiCompatibleProviderProfile.LastProbe` 已有持久化快照) | 08 §1②、10 §二、12 §4 |
| 2 | **离线预设追问首版使用内置文案资源**,后续再由规则知识库动态生成 | 05 §4 |
| 3 | **允许 JsonSchema 降级到 JsonObject**,但必须通过合成图探测及本地 Schema、牌数和规则校验,并明确显示「结构化输出降级」 | 08 §1②、10 §二、12 §4 |

本轮 3 个必须修正项与 2 条 WPF 实现约束同步落地:

- Provider 地址契约:Base URL 必须以 `/` 结尾(否则拼接丢失 `v1` 段)、Path 不允许 `/` 开头(后端 `OpenAiCompatibleOptions.Validate` 直接拒绝)——08 §1②、10 §二、12 §4;
- 「自定义 Header」补齐输入字段:Header 名称(默认 `api-key`)+ Key 前缀(可选,如 `Token `)+ 附加 Header(`AdditionalHeaders`)——08 §1②、10 §二、12 §4;
- 「自动探测」不保存为 Provider 模式(持久化枚举仅 `JsonSchema`/`JsonObject`),实现为 UI 探测动作,成功后保存具体模式——08 §1②、10 §二、12 §4;
- WPF 约束一:打开纠错弹窗、文件选择器或输入法候选窗时不得因 `Deactivated` 退出 InteractiveOverlay,需做自有窗口/输入法激活作用域过滤——12 §3,03/04/05/11 同步;
- WPF 约束二:用户点击其他应用触发 `Deactivated` 退出时不恢复原游戏窗口(避免抢回焦点);仅 Esc、热键、超时、显式关闭才恢复——12 §3,03/04/05/11 同步。
