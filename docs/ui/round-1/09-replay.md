## 2. 巡目时间线规格

- 横向节点条(高 64):x 轴 = 巡,节点 = 关键事件(摸/打/吃/碰/杠/翻牌定癞/风险跳升/和牌),图标区分类型;自家行动节点实心,他家空心;风险跳升节点 Warning 色 + `险` 文字标记;和牌节点 Danger/品牌色 + `和` 字;
- 当前定位 = 2px 品牌竖线 + 节点外圈;点击任意节点/巡刻度跳转;键盘 `←/→` 按事件步进,`↑/↓` 按巡步进;
- 下方跳转控件:`第N巡`下拉(全部巡)+ 首/上/下/终局按钮;**跳转不依赖任何媒体缓冲**,纯状态重建(事件溯源优势,在 UI 上体现为瞬时)。

## 3. 左右双区规格

**左:当时状态快照**(只读迷你牌桌):复用 07 号文件数字牌桌结构,牌降为 Tile.S/M,去掉所有交互按钮,加只读水印角标 `历史快照 · 第6巡`;低置信度历史观察以琥珀虚线保留显示(诚实呈现"当时系统就不确定")。

**右:事件与建议对照**:

| 区块 | 内容 |
|---|---|
| 当时建议 | 建议牌(Tile.M)、向听、进张数、推荐等级(高/中/低,非概率)、`[为什么这样建议▸]`(展开同 05 号文件 §3 四层解释,内容为**当时**计算依据,快照数据;含当时的参考经验与检索审计链接) |
| 实际动作 | 用户实际打出的牌 + 与建议是否一致(`✓一致` / `✗不一致(实际打X)` / `未知`)+ 决策耗时;不一致时两牌并排对比 |
| 风险变化 | 三家各一行`档→档`变迁 + 触发事件标注(如`第5巡碰八筒后上调`);用 ▲▼ 图标 + 文字,不只靠颜色 |
| 本巡事件 | 该巡全部事件列表(玩家/动作/牌/识别置信度/来源) |
| 操作 | `[✎ 标记识别错误]`(打开纠错弹窗,范围多一项"更正复盘记录")、`[查看完整事件JSON]`(Mono 字体抽屉,可复制) |

## 4. 建议采纳统计(页头右侧小卡)

`本局建议 14 次 · 采纳 11 · 不一致 2 · 未知 1` —— 供后期策略适应记忆参考(架构 6.5),仅统计展示,不做评价性文案。

## 5. 状态覆盖

| 状态 | 呈现 |
|---|---|
| 空(无历史牌局) | 空态:`还没有已完成的牌局` + 说明(牌局结束后自动生成复盘) |
| 牌局进行中误入 | 顶部 Info 条 `本局尚未结束,复盘将在结束后生成` + [查看当前牌局] |
| 数据缺失(事件被清理) | 涉及巡节点置灰 + `该巡数据已按保留策略清理`;跳转跳过 |
| 识别错误已标记 | 事件行追加 `已纠错` chip,原文与修正并列展示(补偿事件,不删历史) |
| 导出 | JSON(事件+建议+纠错记录);不含截图;导出路径用户自选 |

## 6. 与"当时为什么"的一致性

复盘中的解释必须来自**当时保存的 DecisionSnapshot**,而非重新计算——UI 上以 `快照 · 当时计算` 角标明示;若规则引擎版本已更新,显示 `当前引擎重算结果可能不同` Caption 提示。这是"建议解释与计算结果一致率"指标(架构第 16 节)在 UI 上的落地。
