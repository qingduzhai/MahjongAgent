# 给 Kimi 的 UI 设计提示词 v1

以下内容可以完整复制给 Kimi。第一轮只要求视觉方案和交互原型，不要实现后端、窗口捕获、数据库或真实 AI 调用。

---

你是一名资深 Windows 桌面产品设计师和 WPF 交互设计师。请为一个开源项目设计第一版高保真 UI，并严格按照下面的产品背景、页面范围和交付要求执行。

## 一、产品背景

产品名暂定为 **MahjongAgent / 麻将观察助手**。

这是一个 Windows 桌面 Agent。用户选择一个正在运行的麻将游戏窗口，系统通过多模态视觉观察牌面，将结果转换成结构化牌局状态，并在轮到用户时提供：

- 推荐弃牌；
- 胡牌与听牌提示；
- 有效进张；
- 癞子、皮、红中杠和开口状态；
- 危险牌与放铳风险提示；
- 推荐理由；
- 低置信度识别纠错；
- 牌局复盘。

首个规则集是武汉红中赖子杠，包含开口、二五八将、癞子、皮、红中杠、口口翻和承包等概念。产品只做观察和提示，不自动点击、不自动出牌。

不同游戏窗口的颜色、布局、牌面样式和癞子位置不同。产品会为每种窗口保存长期的 `WindowProfile`，包括布局、皮肤、规则和视觉样本。下次遇到相同窗口时自动加载，不从零理解。

## 二、设计目标

整体体验应当是“专业、冷静、可信的实时分析工具”，而不是赌博网站、棋牌大厅或夸张游戏外挂。

关键词：

- Windows 11 桌面工具；
- 低干扰；
- 信息密度适中；
- 深色但不压抑；
- 玉石、青绿色作为品牌提示；
- 琥珀色表示需要注意；
- 红色仅表示高风险或错误；
- 规则和计算可解释；
- 对模型不确定性保持诚实。

避免：

- 金币、筹码、赌场灯光；
- 大面积鲜红和金色；
- 过度霓虹电竞风；
- 卡通吉祥物抢占主要信息；
- 用颜色作为唯一状态表达；
- 声称“必胜”“绝对安全”“稳赢”。

## 三、视觉系统

请先给出一套完整设计 Token：

- 主背景、次级背景、卡片背景；
- 主文本、次级文本、弱文本；
- 品牌色、成功色、提醒色、危险色和信息色；
- 4/8/12/16/24/32 的间距体系；
- 卡片、按钮、输入框、弹窗和浮层圆角；
- 阴影和描边；
- 中文字体与数字字体；
- 牌面尺寸：小、中、大三档；
- 动效时长和缓动原则。

首选风格方向：深石墨色背景、低饱和玉石绿品牌色、象牙白麻将牌、适度半透明层次。需要同时确保深色牌桌和浅色牌桌上的悬浮层都清楚可读。

麻将牌图形请使用原创的简化矢量风格或占位图，不复制任何具体游戏平台资产。需要包含万、筒、条、东南西北中发白，以及选中、推荐、危险、癞子、皮、低置信度等状态。

## 四、主要信息架构

主窗口采用左侧导航栏：

1. 实时助手
2. 窗口档案
3. 牌局复盘
4. 规则与知识
5. 设置

窗口顶部需要持续显示：

- 当前连接状态；
- 正在监控的窗口；
- 当前窗口档案名称和匹配置信度；
- 暂停/恢复；
- 隐私状态；
- API 状态。

## 五、必须设计的页面

### 1. 首次启动与隐私引导

内容：

- 产品能做什么、不能做什么；
- 选择多模态服务；
- API Key 输入和安全存储说明；
- 默认不保存完整截图；
- 是否允许保存裁剪后的麻将视觉样本；
- 开始选择窗口按钮。

设计正常、API Key 无效和暂时跳过三种状态。

### 2. 选择目标窗口

以卡片形式展示可选择窗口：

- 窗口缩略图；
- 窗口标题；
- 进程名称；
- 是否匹配到既有档案；
- 档案名称和匹配度；
- 创建新档案或使用已有档案。

包含无窗口、窗口最小化、捕获权限不足状态。

### 3. 首次视觉标定

核心布局：左侧是牌桌预览，右侧是识别结果和步骤。

标定内容：

- 自家手牌区；
- 四家弃牌河；
- 四家副露区；
- 癞子/皮/翻牌区域；
- 当前玩家提示；
- 剩余牌数；
- 规则识别。

在牌桌预览上使用低干扰彩色框和标签。支持“模型识别正确”“手动调整区域”“暂时不确定”。展示正在创建 `WindowProfile` 的过程。

### 4. 实时助手主界面

这是最重要的页面，主窗口基准尺寸 1280×800，最低尺寸 1024×640。

页面包含：

- 当前手牌的大尺寸牌面；
- 癞子、皮和翻牌；
- 推荐弃牌卡片，必须是视觉焦点；
- 备选动作及其差异；
- 向听/听牌状态；
- 有效进张及剩余数量；
- 开口数、翻数、巡目和牌局阶段；
- 四家弃牌和副露的简化概览；
- 危险度提示；
- 最近事件时间线；
- “为什么”解释入口；
- 当前识别置信度；
- 纠错按钮。

推荐示例文案：

> 建议打 9条  
> 保持一向听，有效进张 12 张；5筒已见三张，继续保留价值较低。  
> 备选：东风。风险更低，但损失清一色发展可能。

危险提示必须用“低/中/高风险”“相对安全”“信息不足”，不要使用“绝对安全”。

### 5. 桌面悬浮提示层

设计三种形态：

1. 紧凑：只显示推荐牌、风险和置信度；
2. 展开：显示推荐理由、备选牌和有效进张；
3. 隐藏：只留一个低干扰恢复按钮。

要求：

- 默认不抢焦点；
- 可拖动；
- 支持固定到目标窗口边缘；
- 能暂停提示；
- 清晰标识低置信度；
- 不遮住游戏手牌和操作按钮；
- 给出 360×160 左右的紧凑版示例。

### 6. 识别纠错弹窗

展示：

- 模型识别的牌；
- 第二候选；
- 当前局部视觉证据；
- 用户可以选择正确牌或标记为未知；
- “仅修正本局”与“同时改进该窗口档案”；
- 长期保存视觉样本时的隐私说明。

需要突出区别：候选观察不等于正式牌局事实。

### 7. 窗口档案管理

展示所有 `WindowProfile`：

- 档案名称；
- 游戏窗口或平台；
- 皮肤预览；
- 规则配置；
- 最近使用时间；
- 识别成功率；
- 版本号；
- 保存的视觉样本数量。

操作：重新标定、复制档案、回滚版本、导出、删除。删除操作必须有明确确认。

### 8. 牌局复盘

使用横向事件时间线：

- 每一巡的摸牌、出牌、吃碰杠；
- 当时 Agent 建议；
- 用户实际动作；
- 风险变化；
- 可跳转到某个状态；
- 查看“当时为什么这样建议”；
- 标记识别错误。

不要设计成视频播放器，应突出结构化事件回放。

### 9. 规则与知识

内容：

- 当前规则档案；
- 开口翻/口口翻；
- 癞子、皮、红中杠；
- 胡牌类型；
- 已验证和待确认规则；
- 规则来源链接；
- 不同来源发生冲突时的提示。

### 10. 设置

分组：

- 多模态服务与 API；
- 截图和视觉样本隐私；
- 提示方式；
- 悬浮层；
- 数据保留时间；
- 档案导入导出；
- 日志与诊断；
- 关于和开源许可证。

## 六、必须覆盖的状态

每个关键页面至少考虑：

- 空状态；
- 加载状态；
- 正常状态；
- 低置信度；
- API 超时；
- API Key 无效；
- 目标窗口丢失；
- 窗口布局发生变化；
- 牌局状态矛盾；
- 离线或暂停；
- 牌局结束。

## 七、交互要求

- 高频操作不超过两步；
- 推荐牌与用户纠错都支持键盘快捷键；
- 任何 AI 推测都显示置信度或不确定状态；
- 不要用长篇自然语言占满实时界面；
- 主界面先给结论，再允许展开解释；
- 颜色、图标和文字共同表达风险；
- 所有删除、重置和档案覆盖操作需要确认；
- 用户可以随时暂停捕获和清除当前牌局。

## 八、技术约束

最终客户端使用 C#、.NET 10 和 WPF。设计必须能够自然映射为 XAML：

- 避免依赖浏览器专属 CSS 滤镜；
- 避免复杂自由曲面和难以复现的材质；
- 优先使用 Grid、StackPanel、Border、ItemsControl 等可实现布局；
- 所有组件给出可复用名称和状态；
- 不实现后端、数据库、真实窗口捕获和真实 API 请求；
- 前端原型数据使用固定 Mock 数据；
- UI 与状态通过 ViewModel/Command 概念连接，不直接写业务规则。

## 九、第一轮交付内容

第一轮请先交设计，不要一次性生成完整工程代码。依次输出：

1. 产品视觉方向说明；
2. 设计 Token 表；
3. 信息架构；
4. 10个页面的文字线框说明；
5. 实时助手、首次标定、悬浮层、纠错弹窗、窗口档案、牌局复盘六张高保真 UI 稿；
6. 所有关键组件及状态；
7. 页面交互流程；
8. WPF 落地注意事项；
9. 仍需产品方确认的问题。

高保真稿需要至少展示：

- 1280×800 主窗口；
- 360×160 紧凑悬浮层；
- 中文真实文案；
- 武汉麻将示例牌面；
- 正常和低置信度两类状态。

请在第一轮结尾停止，等待我们审核视觉方向。未经确认，不要继续生成大量 XAML 或工程代码。
