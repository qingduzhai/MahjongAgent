# ADR-0003：统一截图序列来源

- 状态：Accepted
- 日期：2026-07-30

## 背景

Agent 实际需要的是连续的静态截图，而不是游戏进程或视频文件本身。完整牌局视频可以在任意播放器中播放并由窗口捕获器截图，也可以由离线工具按时间戳抽帧，因此适合生成可重复的感知、时序和评测样本。

视频只是截图素材来源，不能自动成为正确标签。一段视频可能缺少自家手牌、跳帧、被剪辑或包含解说遮挡；未经校验的模型观察仍然只是 `candidate`。

## 决策

1. 核心链路依赖 `IFrameSource` 输出的单张静态截图，不直接接收视频流、视频文件或音频。
2. 游戏窗口、视频播放器窗口和可选的离线抽帧工具都输出统一的 BGRA/RGBA/Gray 截图、单调递增的源时间戳和来源 ID。
3. 窗口源是实时、无限、不可寻址的；视频源是有限、可寻址、可按实时或最快速度回放的。
4. 变化检测、视觉标定、多模态观察、时序校验、`GameEvent`、`GameState` 和策略评测全部位于画面源之后，禁止按来源复制两套逻辑。
5. 视觉知识拆为可跨来源复用的 `VisualProfile` 与来源绑定：窗口绑定记录进程/窗口特征，视频绑定记录内容指纹和画面特征。现有 UI 中的 `WindowProfile` 是窗口来源绑定的产品名称，不再承担全部视觉知识。
6. Demo 先用完整牌局视频生成固定截图序列建立可重复评测，同时实现 Windows Graphics Capture；不建设独立的视频理解链路。

## 时间与所有权语义

- `SourceTimestamp` 是牌局时序的主时钟。视频素材快放或离线抽帧不能改变截图对应的媒体时间；实时窗口使用会话启动后的单调时间。
- `ObservedAtUtc` 只用于诊断和审计，不用于推断出牌间隔。
- 每个 `CaptureFrame` 独占一段池化像素内存；消费者处理完必须释放。
- `MinimumFrameInterval` 只控制抽帧，不替代变化检测。初次粗扫可低频抽帧，事件附近可回退并密集重放。

## 视频学习与评测边界

- 导入视频产生带来源追踪的 `ImportedSession`，不会直接修改规则或正式长期记忆。
- 只有通过多帧一致性、牌数/规则校验、人工纠错或可信对局记录对齐的事件，才能从候选晋升。
- 训练集、验证集和测试集按完整视频或牌局切分，禁止把同一视频的相邻帧分到不同集合，避免数据泄漏。
- 完整牌局不等于完整信息：若视角不展示当前玩家手牌，只能用于公开信息、对手行为和界面识别任务。
- 默认不复制原视频；保存内容哈希、时间范围、裁剪样本和派生事件。删除或移动原文件后，历史派生记录仍可审计，但不能重新解码。

## 结果

正面结果：感知问题可复现，可批量回归，可在不启动游戏的情况下从牌局视频取得截图样本，同时保持正式产品的窗口监控形态。

代价：离线高速抽帧仍可能需要单独的解码适配器和时间轴控制，但它只是测试工具；实时窗口的 DPI、遮挡、最小化和焦点问题仍需验证。
