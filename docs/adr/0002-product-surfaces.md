# ADR-0002：主窗口与悬浮助手的产品职责

- 状态：Accepted
- 日期：2026-07-30

## 决策

MahjongAgent 采用双界面产品形态：

1. 主窗口是配置、运维、诊断和牌局可视化仪表盘；
2. 悬浮助手是牌局进行时的核心交互界面。

系统在后台主动监控目标窗口和牌局变化，不要求用户在局内手动录入手牌或逐巡确认事件。

## 主窗口职责

- 首次引导和 API 配置；
- 目标窗口选择；
- WindowProfile 管理；
- 规则和变体配置；
- 捕获、识别、状态机和 API 运维信息；
- 当前牌局完整可视化；
- 事件流、建议历史和置信度诊断；
- 隐私、数据保留和日志；
- 历史牌局复盘。

主窗口不是用户每巡请求建议的入口。

## 悬浮助手职责

- 自动吸附目标窗口；
- 默认不抢焦点、可鼠标穿透；
- 轮到用户或出现重要风险时主动显示紧凑建议；
- 非用户回合以低干扰方式显示对手牌型倾向、可能听牌状态和喂牌风险；
- 通过快捷键展开详细策略；
- 显示推荐牌、备选牌、风险和置信度；
- 支持暂停、隐藏和临时交互；
- 不要求用户输入牌面。

## 显示层级

悬浮助手包含三个层级：

1. 待机胶囊：连接、巡目、识别健康度；
2. 紧凑建议卡：当前推荐、风险、置信度；
3. 详细策略面板：理由、备选、有效进张和防守信息。

## 共享状态

主窗口和悬浮助手只能通过只读 ViewModel 消费同一个 `GameState` 与 `DecisionSnapshot`。任何 UI 都不能自行推导或修改正式牌局事实。

## 后台行为

- 主窗口关闭后默认最小化到托盘；
- 后台继续捕获、观察、更新状态和计算策略；
- 用户可以通过全局快捷键呼出悬浮助手；
- 目标窗口消失或捕获异常时，悬浮助手降级为状态警告；
- 低置信度时暂停强建议，不要求用户在关键操作时立即纠错。

## 提醒策略

- 用户回合自动展开紧凑建议卡；
- 对手普通动作只更新待机信息条，不反复弹窗；
- 对手疑似听牌、明显牌型倾向、承包风险和下家吃牌风险显著变化时可以主动提醒；
- 对手手牌属于隐藏信息，UI 使用“倾向”“可能”“风险”而不是确定断言；
- 详细面板保留基于当前牌局状态的自然语言追问。

## 目标窗口选择

主仪表盘提供三种目标选择方式：

1. 带实时缩略图、进程和档案匹配度的窗口卡片列表；
2. 将准星拖到实际窗口上的精确选择方式；
3. 捕获单独屏幕区域的高级兜底方式。

首次由用户明确选择。以后仅在发现唯一且高置信度匹配的已知窗口时自动连接；多候选时要求用户选择。第一版同时只监控一个目标窗口。
